CLOSHA 분석 스크립트 작성 규칙 1.0

작성일: 2026-10-07

이 문서는 CLOSHA 파이프라인 노드에서 실행되는 분석 스크립트(Bash, R, Python)의 작성 규칙이다. 실행 이미지(DEF) 규칙은 docs/CLOSHA_DEF_Generator_Agent_v1.md를 따른다. 이 문서는 scripts/ATAC-seq, scripts/Retip의 기존 스크립트와 운영 실행에서 확인한 문제를 바탕으로 정리했다.

## 1. 위치, 이름, 버전
- 위치: `scripts/{파이프라인명}/`. 예: `scripts/ATAC-seq/`, `scripts/Retip/`.
- 이름: `{모듈명}.{주버전}.{부버전}.{확장자}`. 예: `ATAC_QC.1.0.R`, `retip_predict.1.0.py`, `organellar_filter.1.0.sh`.
- 지원 언어: Bash(`.sh`), R(`.R`), Python(`.py`).
- 첫 줄(shebang)은 경로를 고정하지 않는다: `#!/bin/bash`, `#!/usr/bin/env Rscript`, `#!/usr/bin/env python3`.
- 한 파이프라인 노드에 스크립트 하나를 둔다. 같은 실행 이미지를 여러 스크립트가 함께 쓸 수 있다(예: bx_atac_qc 이미지 = ATAC_QC + ATAC_QC_plot).
- 업체가 제공한 보조 스크립트(빌드, 예제 재현, 그림 생성 등)는 분석 스크립트가 아니므로 `scripts/`에 두지 않고 해당 `defs/{파이프라인명}/` 아래 원본 보관 위치에 둔다.

### 1.1 버전 관리
- 동작(입력 해석, 결과 내용, 필터 기준, 출력 구조)이 바뀌면 기존 파일을 고치지 않고 **새 버전 파일**을 만든다. 예: `ATAC_QC.1.0.R` → `ATAC_QC.1.1.R`.
- 이전 버전은 지우지 않는다. 이전 결과를 같은 조건으로 재현할 수 있어야 한다.
- 새 버전 파일의 맨 위(shebang 바로 아래)에 이전 버전과의 차이를 적는다.
  ```
  # Version 1.1 (changes from ATAC_QC.1.0.R):
  #   Tn5 shift and nucleosome splitting read the bamQC clean BAM ...
  ```
- 부버전: 같은 실행 이미지에서 돌아가는 변경. 주버전: 입력·출력 형식이 호환되지 않거나 실행 이미지(DEF)가 바뀌어야 하는 변경.
- 오타, 주석, 로그 문구만 고친 경우는 같은 버전에서 수정할 수 있다.
- 새 버전이 새 패키지나 도구를 필요로 하면 DEF도 새 버전으로 만든다. 같은 이미지로 충분하면 DEF는 그대로 두고, DEF 주석의 대상 스크립트 목록만 갱신한다.

## 2. 실행 환경
- 스크립트는 실행 이미지 안에서 `apptainer exec <sif> <인터프리터> <스크립트> <인자>` 형태로 실행된다. 스크립트 자체는 이미지에 넣지 않는다(코드가 이미지에 포함된 패키지인 경우는 예외. 예: Retip의 mdcc).
- 도구는 **이름으로만** 호출한다(`samtools`, `macs3`, `Rscript`). 이미지 내부 절대 경로(`/opt/bio/bin/...`, `/usr/local/bin/...`)를 스크립트에 쓰지 않는다. 위치는 이미지의 PATH가 정한다.
- 실행 중 외부 네트워크에 접속하지 않는다. 패키지 설치(`install.packages`, `BiocManager::install`, `pip install`, `conda install`)나 데이터 다운로드를 하지 않는다. 필요한 것은 DEF에서 설치한다.
- 필요한 도구·패키지가 없으면 시작할 때 확인하고, 이미지를 확인하라는 오류로 멈춘다(`command -v`, `requireNamespace`, `importlib.util.find_spec`).
- 운영 설정상 실행 시 호스트 home과 `/tmp`가 연결된다. home의 사용자 설정(`~/.Rprofile`, `~/.local` 등)에 의존하지 않는다.

## 3. 인자
- 기본 형식은 `key=value`다. 모든 스크립트가 받아야 한다.
- 플랫폼이 `--key value` 형식으로 넘기는 경우가 있으므로 새 스크립트는 `key=value`, `--key=value`, `--key value`를 모두 받는 것을 권장한다.
- 값 양끝의 따옴표(`"`, `'`)는 제거한다.
- 키 이름은 `^[A-Za-z_][A-Za-z0-9_]*$`만 허용한다. 모르는 키는 오류로 멈춘다.
- Bash에서 `declare`로 변수를 만들 때는 보호 변수(`IFS`, `UID`, `EUID`, `PPID`, `BASHOPTS`, `BASHPID`)를 막는다. 가능하면 허용 키 목록을 둔다.
- 이름 규칙:
  | 용도 | 이름 |
  |---|---|
  | 입력 파일 1개 | `input_file` |
  | 입력 폴더 | `input_dir` |
  | 결과 폴더 | `output_dir` |
  | 결과 파일 1개 | `output_file` |
  | 앞 노드의 결과 폴더를 받을 때 | `input_dir` (앞 노드의 `output_dir`를 그대로 연결) |
- 선택 인자는 반드시 기본값을 갖는다. **빈 값은 기본값과 같게 동작**해야 한다(플랫폼에서 빈 값이 넘어올 수 있다).
- 선택형 값은 허용값 목록으로 검사한다(예: `model`은 `RP`, `HILIC`, `auto`).
- "자동"이 의미 있는 옵션은 `auto` 값을 둔다. 예: 입력 표에서 모드 읽기(`model=auto`), 할당 CPU 사용(`cpus=auto`), 앞 노드 기록에서 단위 읽기(`rt_unit=auto`).
- XLSX 시트처럼 이름으로 고르는 값은 이름을 받는다. 번호를 받지 않는다.

## 4. 머리 주석
스크립트 맨 위에 아래 항목을 쓴다. 이 내용이 CLOSHA 모듈 등록(Input/Output/Option 설명)의 근거가 된다.
- Usage: 기본 실행 형태
- Example: 실제 실행 예(필요하면 `apptainer exec` 포함)
- Arguments: 이름, 필수/선택, 형식, 기본값, 허용값, 설명
- Outputs: `output_dir` 아래에 생기는 파일과 폴더
- Logs: 로그 위치와 내용
- 입력 옆에 파일을 만들거나(.bai, .fai) 이전 결과를 지우는 등 주의할 동작

## 5. 입력 검사
- 시작할 때(무거운 작업 전에) 필수 인자, 파일·폴더 존재, 확장자, 허용값을 검사한다.
- 입력 표의 필수 컬럼과 이름 규칙을 검사하고, 무엇이 빠졌는지 오류 메시지에 적는다.
- 입력이 `output_dir`(특히 재실행 때 지워지는 부분) 안에 있으면 멈춘다.
- 앞 노드의 결과를 입력으로 받을 때는 필요한 파일(예: manifest, model 폴더)이 있는지 확인한다.

## 6. 출력과 재실행
- 결과는 `output_dir` 아래에만 쓴다.
- 로그는 `output_dir/logs/`에 둔다. 재실행해도 로그는 지우지 않고 쌓는다.
- 재실행 시 이전 결과는 스크립트가 정리한다. 정리 범위는 다음 중 하나로 고정하고 머리 주석에 적는다.
  - 권장: 스크립트가 만드는 결과 폴더만 지운다(예: `output_dir/result/`).
  - 기존 방식: `output_dir` 아래에서 `logs/`를 뺀 전부를 지운다(ATAC-seq 1.0 스크립트).
- 지우기 전에 다음을 확인하고, 하나라도 맞지 않으면 지우지 않고 멈춘다.
  - 대상이 `/`나 빈 경로가 아니다.
  - 대상이 symlink가 아니고, 실제 위치가 `output_dir` 아래다.
  - 입력 파일·폴더가 지울 대상 안에 있지 않다.
- 결과 하위 구조는 단계 번호를 붙여 고정한다(예: `01_fragment_size`, `02_bam_qc`, ...). 다음 노드가 읽는 파일은 경로를 바꾸지 않는다(예: `05_metadata/atac_qc_manifest.tsv`, `result/model/`).
- 다음 노드가 필요로 하는 정보(사용한 설정, 단위, 모드 등)는 결과 폴더의 manifest에 남겨, 다음 노드가 `auto`로 읽을 수 있게 한다.

## 7. 로그와 출력 스트림
- 로그 파일 이름: `logs/<YYYYMMDD_HHMMSS>_<PID>.log`. stderr를 따로 남기면 같은 이름의 `.err`.
- **stdout**: 진행 정보. **stderr**: 오류와 경고. 둘을 합치지 않는다. 외부 도구를 실행할 때도 stdout과 stderr를 나눠 받는다.
- 로그 시작에 남길 것: 모듈 이름, 로그 파일 경로, 시작 시각, 모든 파라미터(기본값이 적용된 최종값, `auto`면 실제 결정값과 요청값), 실행하는 외부 명령.
- 로그 끝에 남길 것: 결과 위치, 요약(처리·건너뜀·실패 수), 종료 시각.
- 메시지 접두어: `ERROR:`(멈추는 오류), `WARNING:`(계속 진행하는 문제).
- 일부 대상을 건너뛰면 대상별 사유를 로그와 요약 표에 남긴다. 모두 건너뛰면 `WARNING`으로 분명히 알린다.
- 라이브러리가 내는 무해한 경고(예: AutoGluon의 torch 없음 경고)는 그대로 stderr에 남는다. 사용자 안내가 필요하면 머리 주석이나 모듈 설명에 적는다.

## 8. 종료 코드
- 성공: 0. 실패: 0이 아닌 값(보통 1).
- 외부 도구가 실패하면 그 종료 코드를 확인하고 실패로 끝낸다(Bash `set -euo pipefail`, R `quit(status = 1)`, Python `sys.exit(code)`).
- 필수 결과가 하나도 만들어지지 않았으면 실패로 끝낸다. 일부만 실패했을 때의 처리(전체 실패 또는 경고 후 성공)는 머리 주석에 적는다.

## 9. 호스트 보호와 금지 명령
- `output_dir` 밖에 쓰지 않는다. 예외적으로 입력 옆에 인덱스(.bai, .fai)를 만드는 스크립트는 머리 주석에 적고, 가능하면 인덱스를 `output_dir`에 만들거나 미리 있는 인덱스를 쓰도록 한다.
- 임시 파일과 캐시는 가능하면 `output_dir` 안(예: `output_dir/tmp/`)으로 지정한다(`TMPDIR`, `MPLCONFIGDIR`, `XDG_CACHE_HOME`, `JOBLIB_TEMP_FOLDER` 등).
- 사이트 명령 차단 목록(Java 정규식, 줄 단위, 주석 줄도 검사됨)에 걸리지 않게 쓴다. 2026-10-07 기준 목록:
  | 패턴 | 대신 쓰는 방법 |
  |---|---|
  | `\bmv\b` | 복사 후 원본 유지(`cp`) 또는 처음부터 최종 위치에 쓰기 |
  | `\bcd\b` | 절대 경로 사용, 하위 셸 이동 금지 |
  | `\bkill\b`, `\bkillall\b`, `\bpkill\b` | 사용하지 않음 |
  | `\bhostname\b`, `\bservice\b`, `\bsystemctl\b` | 사용하지 않음. 주석과 설명문에서도 이 단어를 피함 |
  | `\bfind\s+/\S*\s.*-exec\s+rm\b`, `\bfind\s+/\S*\s.*-delete\b` | 삭제가 필요하면 6절 규칙의 고정 대상만, 언어 함수로(R `unlink`, Python `shutil.rmtree`) |
  | `/BiO/K-BDS/USER/`, `/etc/passwd\b` | 참조하지 않음 |
  | `\bchmod\s+-R\b` | 사용하지 않음 |
  | `\brm\s+(-\S+\s+)*/(mnt\|data\|scratch\|home\|var\|tmp\|etc\|usr\|bin\|opt\|...)` | 절대 경로를 직접 지우지 않음 |
- 목록은 사이트에서 바뀔 수 있다. 등록 전에 최신 목록으로 스크립트 전체를 검사한다.
- 해시값처럼 긴 문자열에 짧은 단어가 우연히 섞여 걸릴 수 있다. 단어 경계(`\b`)가 없는 패턴이 있으면 사이트 관리자에게 수정을 요청한다.

## 10. 자원
- CPU 수는 고정하지 않는다. 기본값 `cpus=auto`로 실행 환경에 할당된 코어 수(affinity, cgroup, `SLURM_CPUS_PER_TASK` 중 작은 값)를 쓰고, 숫자를 받으면 할당량을 넘지 않게 줄인다.
- 계산 라이브러리 스레드(`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`)를 같은 값으로 맞춘다.
- 실제 사용한 CPU 수를 로그에 남긴다.

## 11. 등록 전 확인 목록
- [ ] 위치와 이름이 `scripts/{파이프라인}/{모듈}.{주}.{부}.{확장자}` 형식이다.
- [ ] 동작이 바뀌었으면 새 버전 파일이고, 맨 위에 변경 내역이 있다.
- [ ] 머리 주석에 Usage, Example, Arguments(필수/기본값/허용값), Outputs, Logs가 있다.
- [ ] `key=value`(권장: `--key value` 포함)를 받고, 빈 값은 기본값으로 동작한다.
- [ ] 필수 인자, 입력 존재, 허용값을 시작할 때 검사한다.
- [ ] 결과와 로그가 `output_dir` 아래에만 생기고, 재실행 정리 범위와 확인 절차가 있다.
- [ ] stdout과 stderr를 나누고, 실패하면 0이 아닌 코드로 끝난다.
- [ ] 도구를 이름으로 부르고, 실행 중 설치·다운로드가 없다.
- [ ] 사이트 명령 차단 목록에 걸리는 줄이 없다(주석 포함).
- [ ] CPU 수를 고정하지 않았다.
- [ ] 실행 이미지에서 실제 입력 또는 예제 입력으로 한 번 이상 실행해 보았다.
